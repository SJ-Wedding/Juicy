# JUICY 파트너 게시판

카페 바이저가 점주들에게 신메뉴 제조법 영상, 공지사항, 건의함/FAQ, 자료실을 안내하는 내부 게시판입니다.
별도 서버 없이 정적 HTML + Supabase(DB/인증)만으로 동작하며, GitHub Pages로 배포합니다.

## 폴더 구조

```
juicy-board/
├─ index.html          홈 대시보드
├─ login.html          로그인
├─ recipes.html         신메뉴 레시피 (목록 + 상세)
├─ notices.html         공지사항
├─ suggestions.html     건의함 · FAQ
├─ orders.html          본사 발주 요청
├─ resources.html       자료실
├─ company.html         업체 정보
├─ assets/
│  ├─ style.css         공용 디자인
│  ├─ supabaseClient.js Supabase 연결 설정 (URL/키를 여기에 입력)
│  └─ app.js            공용 로그인 체크 / GNB 렌더링 헬퍼
└─ sql/
   └─ schema.sql        Supabase에 실행할 테이블/보안정책 스크립트
```

---

## 1단계. Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com) 에서 새 프로젝트를 만듭니다. (Free 플랜으로 시작 가능)
2. 왼쪽 메뉴 **SQL Editor** 로 들어가서 `sql/schema.sql` 파일 내용을 전체 복사해서 붙여넣고 실행(Run)합니다.
   - `profiles`(점주/바이저 정보), `notices`(공지), `recipes`(레시피), `faqs`, `suggestions`(건의사항), `suggestion_replies`(답변), `resources`(자료실), `companies`(업체 정보), `supply_requests`/`supply_request_comments`(본사 발주) 테이블과 보안 정책(RLS)이 한 번에 생성됩니다.
3. 왼쪽 메뉴 **Project Settings > API** 로 들어가서 `Project URL` 과 `anon public` 키를 복사해둡니다.

## 2단계. 코드에 Supabase 정보 연결

`assets/supabaseClient.js` 파일을 열어 두 값을 방금 복사한 값으로 바꿔주세요.

```js
const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi....";
```

(anon key는 공개되어도 되는 키입니다. 실제 접근 권한은 Supabase의 RLS 정책이 통제합니다. `service_role` 키는 절대 이 파일에 넣지 마세요.)

## 3단계. GitHub로 배포 (도메인)

1. GitHub에서 새 저장소를 만들고(예: `juicy-board`), 이 폴더 안의 파일 전체를 업로드/푸시합니다.
2. 저장소의 **Settings > Pages** 로 들어가서 Source를 `main` 브랜치, 폴더는 `/ (root)` 로 설정 후 저장합니다.
3. 몇 분 뒤 `https://<계정이름>.github.io/juicy-board/` 형태의 주소가 생성됩니다. 이 주소를 점주들에게 공유하면 됩니다.
4. 회사 도메인을 따로 연결하고 싶다면 같은 Pages 설정 화면의 **Custom domain** 에 도메인을 입력하고, 도메인 등록업체(가비아 등)에서 CNAME 레코드를 GitHub Pages 주소로 설정하면 됩니다. (필수는 아니며, 없어도 github.io 주소로 바로 사용 가능합니다.)

## 4단계. 계정 생성 방법 (바이저 → 점주)

로그인/계정 생성은 Supabase Auth가 처리하며, 이번 구성은 **바이저가 점주 계정을 직접 만들어주는 방식**입니다 (점주가 스스로 가입하는 화면은 만들지 않았습니다).

1. Supabase 대시보드 왼쪽 메뉴 **Authentication > Users** 로 이동합니다.
2. **Add user** 버튼 클릭 → **Create new user** 선택.
3. 점주 이메일과 임시 비밀번호를 입력합니다. (예: `store01@juicy.com`)
4. 같은 화면의 **User Metadata (JSON)** 항목에 아래처럼 입력합니다.

   ```json
   { "store_name": "역삼점", "role": "owner" }
   ```

   - 바이저(관리자) 계정을 만들 때는 `"role": "visor"` 로 입력하세요. `role`이 `visor`인 계정만 공지/레시피/자료 작성, FAQ 등록, 건의사항 답변 권한을 갖습니다.
5. 저장하면 `profiles` 테이블에 해당 정보가 자동으로 생성됩니다 (schema.sql에 있는 트리거가 처리합니다).
6. 발급한 이메일/임시 비밀번호를 점주에게 전달하면, 점주는 `login.html`에서 바로 로그인해 사용할 수 있습니다. (비밀번호 변경 기능은 이번 범위에는 포함하지 않았습니다 — 필요하시면 추가해드릴 수 있어요.)

점주가 많아져서 바이저가 매번 직접 계정을 만드는 게 번거로워지면, 이후에 "회원가입 신청 → 바이저 승인" 방식으로 바꿀 수도 있습니다.

## 화면(메뉴)별 사용법

**로그인 (login.html)**
발급받은 이메일/비밀번호로 로그인합니다. 계정이 없으면 바이저에게 문의해야 합니다. 로그인하지 않은 상태로 다른 페이지 주소를 직접 입력해서 들어와도, 화면 내용이 그려지기 전에 바로 로그인 화면으로 이동하도록 처리되어 있습니다 (비로그인 사용자에게 내용이 잠깐이라도 노출되지 않습니다).

**홈 (index.html)**
로그인 후 첫 화면입니다. 필독 공지가 있으면 상단 배너로 보여주고, 레시피/공지/건의함·FAQ/본사 발주/자료실/업체 정보 6개 블록을 카드로 보여줍니다. 각 카드를 클릭하면 해당 메뉴로 이동하고, 아래쪽에는 최근 공지사항과 최근 건의사항이 요약되어 표시됩니다.

**신메뉴 레시피 (recipes.html)**
왼쪽에서 카테고리(전체/신메뉴/시즌 메뉴/베이직 메뉴) 탭으로 필터링하고, 레시피 카드를 클릭하면 오른쪽에 상세 정보(제조 영상 링크, 재료, 제조 순서, PDF 다운로드)가 나타납니다.
- **점주**: 조회만 가능합니다.
- **바이저**: 우측 상단 "+ 새 레시피 등록" 버튼으로 새 메뉴를 추가할 수 있습니다. 제조 영상은 파일을 직접 올리지 말고 유튜브(비공개/일부공개)나 구글 드라이브에 올린 뒤 링크만 입력하세요 (Supabase 비용 절약).

**공지사항 (notices.html)**
전체 공지 목록을 최신순(+필독 우선)으로 보여줍니다.
- **점주**: 조회만 가능합니다.
- **바이저**: "+ 공지 작성" 버튼으로 제목/내용/분류를 입력하고, "필독 공지로 상단에 고정" 체크박스를 켜면 홈 화면 배너와 목록 최상단에 강조 표시됩니다.

**건의함 · FAQ (suggestions.html)**
상단 "자주 묻는 질문" 박스는 질문을 클릭하면 답변이 펼쳐지는 아코디언입니다. 그 아래는 건의사항 목록이며, 상태(답변대기/답변완료) 탭으로 필터링할 수 있습니다.
- **점주**: "+ 건의사항 작성" 버튼으로 제목/내용을 남길 수 있고, "익명으로 작성" 체크 시 매장명 대신 "익명"으로 표시됩니다. **본인이 작성한 건의사항과 그 답변만** 볼 수 있습니다 (다른 매장 글은 보이지 않습니다).
- **바이저**: 모든 매장의 건의사항을 조회할 수 있고, "답변대기" 상태인 글에 답변을 입력해 등록하면 자동으로 "답변완료"로 바뀝니다. FAQ 박스 우측의 "+ FAQ 추가" 버튼으로 자주 나오는 질문을 등록할 수 있습니다.

> 건의사항 공개 범위는 화면에서만 숨기는 게 아니라 Supabase DB의 보안 정책(RLS)으로 강제됩니다. 즉 점주 계정으로는 아무리 시도해도 다른 매장의 건의사항 데이터 자체를 서버에서 내려주지 않습니다.

**본사 발주 (orders.html)**
건의함과 같은 구조입니다. 상단 상태 탭(전체/요청/발주완료)으로 필터링합니다.
- **점주**: "+ 발주 요청하기"로 필요한 물품명/수량/요청사항을 남깁니다. **본인 매장이 요청한 발주 내역만** 보입니다.
- **바이저**: 모든 매장의 발주 요청을 조회할 수 있고, "요청" 상태인 건에 확인 내용(예: 입고 예정일)을 입력해 등록하면 자동으로 "발주완료"로 바뀝니다.

**자료실 (resources.html)**
매뉴얼, 서식, 포스터 등 문서 링크 목록입니다. 항목을 클릭하면 새 탭에서 링크가 열립니다.
- **점주**: 조회/다운로드만 가능합니다.
- **바이저**: "+ 자료 등록" 버튼으로 제목/분류/링크를 등록할 수 있습니다. 파일은 구글 드라이브 등에 올리고 공유 링크를 입력하는 방식을 권장합니다 (원한다면 Supabase Storage 버킷을 만들어 그 공개 URL을 넣어도 됩니다).

**업체 정보 (company.html)**
재료·장비 공급업체, AS 센터 등 연락처 목록입니다. (구분/담당자/연락처/이메일/비고 필드로 구성했습니다 — 다른 형태로 바꾸고 싶으시면 말씀해주세요.)
- **점주**: 조회만 가능합니다.
- **바이저**: "+ 업체 등록" 버튼으로 새 업체 정보를 추가할 수 있습니다.

## 참고

- 이 구성은 Free 플랜 기준으로 충분한 사용량(월 게시글 100건 내외)입니다. 다만 Supabase Free 프로젝트는 **7일간 접속이 없으면 자동 일시정지**되니, 실제 운영을 시작하면 Pro 플랜($25/월) 전환을 고려해보세요.
- 지금 구조는 로그인/권한 분기까지 포함된 실제 동작 코드지만, 실서비스로 쓰기 전에 브라우저 몇 개(크롬/사파리, 모바일)에서 한번 직접 로그인부터 글쓰기까지 테스트해보시는 걸 권장드립니다.
